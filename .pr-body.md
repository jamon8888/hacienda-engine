# Unified rehydration contract (issue #147)

## Summary

Implements the core of the unified rehydration contract from issue #147, following **Option 1 of wayfinder dossier #122** (`docs/wayfinder/122-contrat-rehydratation.md`): a single authorization object, `RevealTicket`, replaces the two parallel contracts (A: facade/REST token reveal; B: installation-profile `RehydrationRequest`).

## What is implemented

- **`hacienda-core/src/reveal_ticket.rs` (new)** — the unified contract:
  - `RevealTicket { ticket_id, subject, tenant, dossier_id, document_ids, token_ids, field_scope, justification, requested_at, expires_at, one_shot, approvers, status }` (superset of the issue's field list: `dossier_id` is added because the ACL gate must be pinned at mint time; `status` tracks the lifecycle).
  - `RevealTicketRequest`, `RevealTicketError`, `RevealTicketStatus`, `RevealTicketStore` (in-memory, injectable clock, tenant-scoped keys, `revoke`/`consume`), `DossierAcl` trait + `InMemoryDossierAcl` (fail-closed by default).
  - TTL: default **and** maximum 10 minutes (`MAX_TICKET_TTL_SECS = 600`), shorter TTLs clamped to `[1, 600]`.
  - `HIGH_SENSITIVITY_CATEGORIES` + `is_high_sensitivity_category` — the high-sensitivity threshold (category set: identity docs, payment instruments, health data, credentials), reserved for the double-approval enforcement (see TODOs).

- **`hacienda-core/src/facade.rs`** — two new operations:
  - `mint_reveal_ticket_with_auth`: requires `pii:reveal` **and** dossier membership via `DossierAcl` (`with_dossier_acl` builder; no ACL configured ⇒ minting refused, fail-closed). In-process `Caller::Trusted` can never mint (`TrustedCaller` error) — the MCP/agent surface stays closed by construction. A tenant whose redaction mode is not `RedactionMode::Pseudonymize` — including any future non-reversible mode from #17 — can never produce a ticket (`NonReversibleMode`). Requests are shape-validated (non-empty dossier/documents, token shape check, non-blank justification).
  - `resolve_reveal_ticket_with_auth`: only the ticket's `subject` (holder), once (`one_shot` is always minted as true), before `expires_at`, and only for tokens/documents inside the ticket's scope (`ScopeViolation` otherwise). Resolution reveals through the existing `Pseudonymiser` and writes the attributed `Reveal` audit entry; the caller is necessarily a `Caller::Principal`, so `principal` is never `None` on this human path.

- **`hacienda-api/src/error.rs`** — every reveal-ticket failure collapses to one generic **400** (`InvalidRequest`), except ACL denial which is a **403**. The variants stay distinguishable to operators/logs/tests but not to a client: error shape is never a probing oracle (unknown token / expired / consumed / revoked / out-of-scope are indistinguishable). Unknown tokens surface through the existing coarse `PseudonymError` → 400 mapping (unchanged, fail-closed).

- **`hacienda-mcp/src/lib.rs`** — manifest-level guard test: the agent-facing tool inventory contains no reveal/rehydration tool (the `pii_reveal` tool was already removed from the MCP manifest at `db8d895`; this pins it with a regression test, and the facade additionally refuses ticket minting by `Caller::Trusted`).

## Decisions on the open questions of issue #147 / dossier #122 §4

- **TTL** — default *and* cap of 10 minutes (the maximum dossier §4 Q6 proposes). A shorter TTL may be requested; a longer one is clamped down.
- **One-shot** — non-negotiable on the human path: the facade always mints `one_shot: true`.
- **Double approval** — high-sensitivity threshold defined as a category set (not volume/export), enforcement deferred (TODO below).
- **Unknown token** — fail-closed, same coarse 400 as today, no error oracle.
- **Non-reversible mode (#17)** — a ticket can only exist when the tenant's mode is `Pseudonymize`; any future short non-reversible pseudonym mode is `!Pseudonymize` by construction, so it can never produce a ticket.
- **Fail direction** — no ACL configured ⇒ no ticket at all (reveal is opt-in, never default-allowed); a restart expires every outstanding ticket (in-memory store, fail-closed direction, same posture as key material today).

## Explicit TODOs (documented, not in this PR)

- **Ticket revocation** — `RevealTicketStore::revoke` exists and is unit-tested, but has no facade method / API surface yet.
- **Double approval enforcement** — `approvers.len() >= 2` distinct approvers ≠ subject for high-sensitivity scopes: the `InsufficientApprovers` error variant and `HIGH_SENSITIVITY_CATEGORIES` exist and are reserved; minting stores `approvers` but does not enforce yet (dossier #120 double approval).
- **Xberg document-local map** — the enforcement point is the ticket's `document_ids` (executors must refuse any document not in scope), but `Backend::rehydrate`/`VaultRehydrationAdapter` are not yet wired to tickets; where the map itself lives (facade vs backend store) is still open (dossier #131 §5.3).
- **Audit enrichment** — the `Reveal` audit entry must carry `ticket_id`, `document_id`, `token_id`, `justification`, `approvers`; this requires extending `AuditEntryInput`/`AuditEntry` (and the audit chain + storage schema). Today the entry names the `principal` (never `None` on this path) but not the ticket metadata.
- **`principal` never `None`** — guaranteed on this new path (resolution requires `Caller::Principal`); enforcing it across the other human paths (e.g. `VaultRehydrationAdapter::reveal`, currently `principal: None`) belongs to the backend wiring above.
- **Contract-B convergence** — `RehydrationRequest` becoming a *ticket demand* and `VaultRehydrationAdapter` becoming the ticket *executor* (dossier #122 §5 step 3) is the follow-up step; this PR only lays the core contract down.
- **REST/CLI transport wiring** — mint/resolve routes in `hacienda-api`, plus the `DossierAcl` implementation for real dossier stores.

## Tests

Unit tests cover the full contract matrix: minting without `pii:reveal` → refused (`Authz`); `Caller::Trusted` mint → refused; minting without dossier membership (or with no ACL configured) → `AclDenied`; non-reversible mode (`Mask`) → `NonReversibleMode`; one-shot resolution with principal named in audit, second resolution → `Consumed`; expired ticket → `Expired`; unknown token under a ticket → coarse `PseudonymError` → 400; out-of-scope token/document → `ScopeViolation`; non-holder → `NotHolder`; store-level one-shot/tenant-scoping/revocation; TTL clamping; token-header/high-sensitivity helpers; MCP manifest guard.

Closes #147 (core path; remaining work tracked in the TODOs above).
